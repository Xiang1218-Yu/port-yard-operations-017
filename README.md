# HarborGrid · 港口集装箱堆场作业协同与闸口调度系统

React + Vite + TypeScript 前端，Node.js + Express + TypeScript 服务端。面向中型集装箱码头，把船期、箱务、堆场区块、闸口预约、设备作业和异常闭环放在同一套作业控制台中。

## 启动

```bash
npm install
npm run dev
```

前端默认 Vite 端口 5178，API 默认 `http://localhost:4107`。

## 业务能力

- 船舶航次、泊位窗口、计划/已完成翻箱和延误风险
- 箱号、尺寸、冷藏温度、危险品级别、海关状态、进出口/中转流向
- 堆场区块容量、堆存热度、冷藏插座、危险品隔离和设备可达性
- 闸口预约时隙、车道、OCR/称重/封志校验状态与同车冲突检测
- 岸桥、场桥、集卡、正面吊设备池和约束感知任务队列
- 自动堆位推荐、冷藏/危险品约束、海关查验阻塞、任务指派审计
- 泊位窗口重排：ETA 延误/提前时把窗口、岸桥、装卸任务、闸口预约、未完成箱务一起重算，多方案比选后确认批量更新
- React 控制台支持船期驾驶舱、闸口操作、堆场热区、设备任务与泊位窗口重排操作

### 泊位窗口重排模块

`POST /api/replan/sessions` 触发重排（航次 + 新 ETA + 原因），返回同一快照下可比较的方案：

- `sequence` 顺延同泊位窗口（级联消除后续航次冲突）、`berth-switch` 改靠空闲泊位、`compress` 压缩在泊加班加桥、`anchorage-hold` 提前到港锚地等待、`eta-only` 仅改 ETA（基线反例，不推荐）
- 每套方案给出评分明细、受影响航次/任务/岸桥/预约/箱务指标，以及"航次窗口变化 → 具体任务平移/冻结/换桥 → 预约与箱务"的完整影响链
- `/select` 选方案、`/eta` 处理重排中又收到的新 ETA（原方案作废重算）、`/confirm` 两阶段校验（已开始作业不可回滚、泊位实时占用、岸桥被其他航次锁定）+ 逐项写入事务（部分失败整批逆序回滚）、`/cancel` 按会话基线快照恢复
- 推迟/提前原因写入航次窗口历史、任务 `rescheduleNote`、预约 `exception`、箱务 `lastEvent` 与审计事件

当前使用内存种子数据，领域服务通过 REST API 暴露，后续可接入 TOS、OCR、称重、RTG 遥测、预约配额和优化求解器。
